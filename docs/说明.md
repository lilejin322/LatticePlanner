# 这个仓库到这里为止

这是 Apollo lattice 规划器的一份 Python 移植。留下来是为了看规划器自己：多项式、代价、轨迹怎么拼起来，以及每 0.1 秒做一次的约束检查。CommonRoad 只提供现成的路和录下来的车。

它不是交通仿真，也不是一种新的开车方法。检查器说「合格」的时候，车的运动可以已经出界。下面这些就是查到的事实。

## 检查器漏掉的地方

急刹用的备用曲线在每个检查点都回答「没有急动」。那个回答是写死的 0。车停住的时候，加速度从很重的刹车变成 0，这一下发生在两个检查点中间。减速度是 4 m/s² 时，这一下的急动是 40 m/s³，允许的上限是 2。一维检查器听那个写死的回答，所以它说这条刹车合格。

另一条曲线只被检查到它自己结束，这里是 2 秒。规划器还要把它用到 8 秒，办法是让最后的加速度继续保持。速度从 35 m/s 涨到 59 m/s。限速是 40 m/s。结束之后的那段没有再查。

还有一条已经钉住的曲线。1.84375 秒时急动是 −4.03 m/s³，界限是 −4。检查器不看这个瞬间。它只比较 1.8 秒和 1.9 秒两个点上的加速度。曲线结束后加速度被冻住，这两个点的差仍在界限里。一维检查器和笛卡尔检查器都说合格。横向也有同样的洞：0.53125 秒的横向加速度是 −4.38 m/s²，界限是 ±4，0.1 秒的采样没看到。

## 规划器交出来的轨迹

这些输入都不复杂。返回的轨迹仍然不对。

速度为 0、朝向 1 弧度。换到沿路坐标以后，状态是有限的。备用轨迹却给出大约 21 亿米外、速度约 2143 m/s 的点。笛卡尔检查器判速度越界，这条轨迹还是被交出去。

朝向转了 180 度、速度 1 m/s。沿路的速度变成负数。规划器不返回失败，直接抛出 `AssertionError`。

前方 8 米有一辆停着的车。备用轨迹就是上面那条急刹。拼出来的采样在 1.2 秒从加速度 −4 跳到 0，急动 40 m/s³，轨迹仍被返回。

四条录下来的路也有各自的签名。Peach 的备用点远在 10 万米以外。Monzon 同样因为负的沿路速度抛出断言。ZAM 在 0.7 秒那次备用轨迹上，提交点跳离当时的起点。Moissy 在 0.9 秒，速度在 0.1 秒里从 14.13 m/s 降到 13.24 m/s，合 −8.92 m/s²；同一条轨迹上记下的加速度还在允许范围内。

## 记录放在哪里

想再跑一遍：

```bash
python scripts/run_all_planner_checks.py
```

签名还在的时候，这些检查通过。哪一条被修掉了，就把对应记录改成「已经被挡住」，那一项才会失败，提醒人去改记录。

| 文件 | 记着什么 |
|------|----------|
| `scripts/run_lattice_known_failures.py` | 四条录下来的路 |
| `scripts/run_lattice_synthetic_failures.py` | 直道上的三条：停车朝向、反向朝向、急刹急动 |
| `verification/pinned_sampling_gaps.py` | 两个被 0.1 秒采样漏掉的曲线 |
| `verification/verify_backup_jerk.py` | 备用减速把急动报成 0 |
| `verification/verify_extrapolation.py` | 曲线结束后速度冲过 40 m/s |
| `verification/verify_cartesian_jerk.py` | 1.8 秒和 1.9 秒的差合格，中间的急动不合格 |

更细的命令和数值在仓库根目录的 `README.md`。

不再往下加新的洞。洞的类型已经重复：检查点太稀，备用曲线不报急动，曲线结束后还在往外推。
